# 首版需求与边界

首版交付三套独立持久化子系统：院系课程目录、先修关系图、学生成绩与等效协议。各有输入、业务键、版本、裁定和失败反例。目录的同号冲突、图的环路以及学分的撤销是三种不同业务决定，分别有可观察输出；最终资格报告从各账重算，并保存报告历史。

十个决定包含目录来源权威、同号学分争议、停开历史、AND/OR 求值、图环阻断、图适用学年、成绩来源、等效协议、重复抵扣和专业学分类别。三条跨账路径是目录变动使等效重审、停开使新学年图待审、等效撤销使学生资格失效；旧学年证据不可被新学年覆盖。

未实现：跨校学分协议、短学期学时折算、课程大纲差异比对、教学语言要求、学籍休复学窗口、跨专业名额调剂和双学位共享冲突。首版不能声称已支持这些对象。

# 二期：培养方案学期规划核证

在独立采录的培养方案账（必修、任选要求组、逐学期开课、学生起点与学期学分上限）之上，`plan.verify` 整体核算学生最早完成学期：按签发版本的开课记录、目录已发布学分、学期上限、跨学期先修与已认定抵扣排课，先修须早于目标课开学，同修不算已修；同一门课不可填充两个互斥要求组，来源学分不可跨组双花；不允许逐课取最早学期再拼表（学分额度竞争下局部最早会推迟全部目标课）。

开课记录的同版可开/停开冲突构成争议。条件规划假设争议课开设，给出可行逐学期课程表与假设清单；教务处承诺只在所有仍可能有效的解释下都可执行时签发，逐解释保留分支。更早候选学期附关键约束集合（开课、学分上限、先修、抵扣、目录），报告注明所用目录、先修图、抵扣与开课证据。结论追加持久化于 `plan_case`，内容未变不重复落账；开课更正、先修 any/all 改动、抵扣撤销与目录学分修订均联动重核受影响学生的毕业学期，旧结论与原始事件保留不覆盖。

仍未实现：跨校学分协议、短学期学时折算、课程大纲差异比对、教学语言要求、学籍休复学窗口、跨专业名额调剂和双学位共享冲突。
